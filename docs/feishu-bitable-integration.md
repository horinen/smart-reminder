# 飞书多维表格集成方案

## 背景

当前 Smart Reminder 系统主要面向个人项目，数据存储在本地 JSON 文件中。现需要扩展为**全能日程管理助手**，支持工作项目管理，同时满足：

1. 尽量复用飞书现有能力，避免重复造轮子
2. 数据由飞书云端存储，可靠且可跨设备访问
3. 通过 AI 对话交互，而非手动填表

## 方案概述

**核心思路**：将项目数据迁移到飞书多维表格，AI 通过 API 操作数据，用户通过对话完成所有操作。

```
┌─────────────────────────────────────────────────────────────┐
│                      用户对话                                │
│        "刚做完需求文档，花了2小时"                            │
└──────────────────────────┬──────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────────┐
│                    AI Agent (OpenClaw)                       │
│                                                              │
│  解析意图 → 调用脚本 → 操作飞书多维表格 API                    │
└──────────────────────────┬──────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────────┐
│                   飞书多维表格 (Bitable)                      │
│                                                              │
│  ├── 项目表 (Projects)                                       │
│  ├── 成果物表 (Deliverables)                                 │
│  └── 工作记录表 (WorkLogs)                                   │
└─────────────────────────────────────────────────────────────┘
```

## 数据结构设计

在飞书中创建一个多维表格，包含以下三张数据表：

### 1. 项目表 (Projects)

| 字段名 | 字段类型 | 说明 |
|--------|----------|------|
| 名称 | 文本 | 项目名称 |
| 分类 | 单选 | work / personal / learning |
| 描述 | 多行文本 | 项目描述 |
| 截止日期 | 日期 | 可选 |
| 状态 | 单选 | active / paused / completed / archived |
| 备注 | 多行文本 | 可选 |
| 创建时间 | 创建时间 | 自动 |
| 更新时间 | 修改时间 | 自动 |

### 2. 成果物表 (Deliverables)

| 字段名 | 字段类型 | 说明 |
|--------|----------|------|
| 名称 | 文本 | 成果物名称 |
| 项目 | 单向关联 | 关联项目表 |
| 状态 | 单选 | pending / in_progress / done |
| 完成时间 | 日期 | 状态变为 done 时记录 |
| 描述 | 多行文本 | 可选 |
| 创建时间 | 创建时间 | 自动 |
| 更新时间 | 修改时间 | 自动 |

### 3. 工作记录表 (WorkLogs)

| 字段名 | 字段类型 | 说明 |
|--------|----------|------|
| 日期 | 日期 | 工作日期 |
| 项目 | 单向关联 | 关联项目表 |
| 成果物 | 单向关联 | 可选，关联成果物表 |
| 内容 | 多行文本 | 做了什么 |
| 时长 | 数字 | 单位：分钟 |
| 创建时间 | 创建时间 | 自动 |

## 用户交互设计

### 对话模式

用户通过自然语言与 AI 对话，AI 解析意图后调用脚本操作多维表格。

#### 新增项目

```
用户：我在做一个新项目叫"客户管理系统"，工作项目，下个月底要交付

AI：
- 项目名称：客户管理系统
- 分类：工作
- 截止日期：4月30日
确认创建吗？

用户：确认

AI：已创建项目"客户管理系统"。
```

#### 添加成果物

```
用户：客户管理系统有三个关键成果物：需求文档、原型设计、开发上线

AI：已为"客户管理系统"添加 3 个成果物：
- 需求文档（待开始）
- 原型设计（待开始）
- 开发上线（待开始）
```

#### 记录工作

```
用户：刚做完需求文档，花了2小时

AI：
- 项目：客户管理系统（根据上下文推断）
- 成果物：需求文档
- 内容：做完需求文档
- 时长：2小时（120分钟）
确认记录吗？

用户：对

AI：已记录。项目"客户管理系统"的成果物"需求文档"已标记为完成。
```

#### 查询与汇报

```
用户：生成上周周报

AI：【上周工作总结】

项目进展：
- 客户管理系统：完成"需求文档"，总投入 8 小时
- 个人博客：完成"文章撰写"，总投入 3 小时

时间分布：
- 客户管理系统：8小时（72%）
- 个人博客：3小时（28%）

本周完成成果物：2个
总工作时长：11小时
```

## API 集成设计

### 所需权限

在飞书开放平台创建自建应用，申请以下权限：

| 权限 | 说明 |
|------|------|
| `bitable:app` | 获取多维表格信息 |
| `bitable:app:readonly` | 读取多维表格 |
| `bitable:record` | 编辑记录 |

### 脚本设计

| 脚本 | 功能 | API |
|------|------|-----|
| `feishu-bitable-project.mjs` | 项目 CRUD | 新增/查询/更新记录 |
| `feishu-bitable-deliverable.mjs` | 成果物 CRUD | 新增/查询/更新记录 |
| `feishu-bitable-worklog.mjs` | 工作记录 CRUD | 新增/查询记录 |
| `feishu-bitable-report.mjs` | 周报/月报生成 | 查询 + 汇总 |

### 认证方式

复用现有的飞书日历认证机制（user_access_token）。

## 周报/月报生成

### 周报内容

| 模块 | 数据来源 | 生成方式 |
|------|----------|----------|
| 项目进展 | 成果物表 + 工作记录表 | 按项目分组汇总 |
| 时间分布 | 工作记录表 | 按项目统计时长 |
| 成果物完成数 | 成果物表 | 状态=done 的记录数 |
| 日程回顾 | 飞书日历 | 已有日程同步功能 |
| 下周计划 | 成果物表 | 状态≠done 的成果物 |

### 生成触发

- 用户主动请求："生成上周周报"、"本月工作总结"
- 可选：系统定时推送（每周日晚）

## 与现有系统的关系

### 保留的功能

| 功能 | 状态 |
|------|------|
| 提醒系统 | 保留，从多维表格读取项目数据 |
| 日程同步 | 保留，飞书日历集成 |
| 定时任务 | 保留，发送提醒的逻辑不变 |

### 数据源变更

| 数据 | 原存储 | 新存储 |
|------|--------|--------|
| 项目信息 | projects.json | 飞书多维表格-项目表 |
| 成果物 | （无） | 飞书多维表格-成果物表 |
| 工作记录 | （无） | 飞书多维表格-工作记录表 |
| 日程 | schedules.json | 飞书日历（已有） |
| 提醒 | reminders.json | 本地（保留） |
| 提醒历史 | reminder-history.json | 本地（保留） |

## 实现步骤

### 第一阶段：基础集成

1. 创建飞书多维表格（手动，按上述结构）
2. 实现多维表格 API 认证脚本
3. 实现项目 CRUD 脚本
4. 实现成果物 CRUD 脚本
5. 更新 AGENTS.md，集成新脚本

### 第二阶段：工作记录

1. 实现工作记录 CRUD 脚本
2. AI 解析工作汇报意图
3. 关联项目和成果物

### 第三阶段：报告生成

1. 实现周报/月报查询脚本
2. AI 格式化输出报告
3. 可选：定时推送

### 第四阶段：提醒优化

1. 提醒系统读取多维表格数据
2. 根据成果物状态生成提醒
3. 根据工作记录分析项目停滞
